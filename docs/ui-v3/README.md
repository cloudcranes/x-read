# x-read UI v3「刊」——基于后端真实能力的设计

> 设计图：`00-overview.png`（总览）、`01`–`07`（分屏，@2x 786×1746，即 393×873dp）。
> 令牌：`design-tokens.css`。可复现源码：`src/`（HTML + 子集字体，离线可渲染）。
> 本文件是**设计规格**，不含 Kotlin 代码。

---

## 1. 为什么重做，而不是继续改 v2

v2（`docs/ui-design-v2.md`）是在「不知道后端能给出什么」的前提下做的美术收敛：定了宣纸底色、发丝线、四档圆角。落地后真机走查暴露出更根本的问题——**界面没有用上后端已经给出的结构化数据**。

实测后端（`http://127.0.0.1:18081`，2026-10-29）：

```
GET /api/v1/rankings?gender=male&type=reading&page=1
  → 每本带 rank=1、rank_change=0、reading_count=597999、status="1"
  ⚠️ 这条是 **Python 后端**（`x_read/`，走官网接口）的返回；Android App 走的是
  原生核心 `rank_data`，字段集不同，见 §1.1
GET /api/v1/rankings/catalog
  → genders: [male 男频(19 类), female 女频(18 类)]，types: [reading 阅读榜, new 新书榜]
GET /api/v1/books/.../chapters/{id}/reviews
  → total_reviews=41848, paragraphs: [{para_index, count, hot}]
GET /api/v1/search/hot
  → [{word, is_hot}]
```

而 v2 界面里：

| 后端有 | v2 界面 |
|---|---|
| `rank_change`（排名升降） | 完全不显示 ⚠️ 见 §1.1：Android 侧拿不到 |
| `reading_count`（在读人数） | 完全不显示（只显示书名和作者） |
| `gender` 男频/女频 | 没有入口（⚠️ Android 侧核心不给性别维度，§1.1） |
| `status` 连载/完本 | 未解析，不显示 |
| `total`（榜单总条数）、`page` | 只给一个「加载更多」 |
| `total_reviews=41848` | 阅读页只显示「段评 260 条」 |
| `is_hot`（热搜是否热门） | 当普通词处理 |

### 1.1 落地时的实测修正（2026-10-29）

设计初稿假设 Android 端能拿到与 Python 后端相同的字段。**实测推翻了三个假设**：

| 字段 | Python 后端 | 原生核心 `rank_data`（实测） | v3 最终做法 |
|---|---|---|---|
| 名次升降 | `rank` + `rank_change` | ❌ 载荷里没有 `currentPos`/`rankPosDiff` | 名次用**列表下标 + 1**；升降**不做** |
| 在读人数 | `reading_count` | ✅ `read_count`（另有 `read_count_all`，口径不同，不用） | 用 `read_count`，格式 `59.7 万` |
| 连载状态 | `status` | ✅ `creation_status` | `"0"`=完本 / `"1"`=连载（实测口径，见下） |
| 连载章数 | — | ✅ `serial_count` | 详情页章数用目录长度，`serial_count` 备用 |
| 性别维度 | `genders: male/female` | ❌ 无 | **不做**男频/女频切换 |
| 榜单分页 | `page` / `has_more` / `total` | ❌ 固定 30 本，`has_more=false`、`next_offset=0`；且同 offset 重取结果不可复现（见下） | **不做**页码，只显示「TOTAL N 本」 |
| 榜种/分类 | `tabs` / `categories` | ✅ `rank_algo_list`（5 榜种）+ `sub_info_list`（19 分类） | 榜种标签条 × 分类芯片 |
| 分类字段 | `category` | ⚠️ `category` 被上游当**社交证明位**用，实测出现 `116个老书虫在看` | 新增 `ContentParser.parseCategory()`：优先 `pure_category_tags`，排除计数文案 |

实测方法：临时给 debug 构建加响应落盘探针 → 真机走一遍榜单 → `adb pull` 出 12 份完整载荷
（最大 616KB，单条 JSON）→ 逐字段核对。**探针已完全回滚**，release 包无任何残留。

两个连带发现：

1. **`category` 字段不可靠。** 上游把它当社交证明位用，实测见到
   `category = "116个老书虫在看"`——真分类在 `pure_category_tags = "都市日常,仕途"`。
   已加 `ContentParser.parseCategory()`：优先 `pure_category_tags` → `category`（排除「在看/人在读/书友」等计数文案）→ `tags`。有 5 个单测钉住。
2. **`creation_status` 口径必须实测。** 抓 40 条榜单样本交叉核对末章标题：
   `"0"` 的 7 条末章全是「完结/番外/大结局」，`"1"` 的 33 条均无完结信号。
   所以 **`"0"` = 完本，`"1"` = 连载**（与直觉相反）。端到端验证：完本榜 6 行全部显示「完本」。

**v3 的核心主张：把这些数字变成界面的骨架。** 榜单不是货架，是一份带排名的刊物；数字向右对齐成列，读起来像统计表而不是商品列表。

## 2. 设计方向

**「刊」= 报纸/期刊的编辑设计 + 数据表的对齐纪律。**

三条硬规则（违反任意一条即视为返工）：

1. **层级靠字重、发丝线、留白**，不用阴影、不用圆角气泡、不用彩色底块。
2. **所有数字等宽对齐**（`font-variant-numeric: tabular-nums`），排名、在读人数、章数、字数、百分比一律右对齐成列，扫读时能竖着比。
3. **圆角只有三档**：卡片/输入/芯片 `0`（直角）、封面 `10`、底部抽屉 `20`。刊物不该有气泡感。

明确禁止：渐变背景、玻璃拟态、彩色投影、emoji 当图标、同屏三种以上圆角、纯黑纯白阅读底。

## 3. 设计令牌

### 3.1 颜色（外壳）

浅色「纸白」：

| 语义 | 值 | 用途 | 对比度（对 `#FBFAF7`） |
|---|---|---|---|
| `bg` | `#FBFAF7` | 页面底（偏冷纸白，不是米黄） | — |
| `surface` | `#FFFFFF` | 卡片面 | — |
| `ink` | `#16150F` | 标题、正文 | **17.52:1** |
| `ink-2` | `#5C594F` | 次要文字 | **6.71:1** |
| `ink-3` | `#6E6A5C` | 三级文字、单位、序号 | **5.19:1**（在 `#F4F2EC` 条带上 4.84:1） |
| `rule` | `#E6E2D8` | 发丝线 | 装饰 |
| `rule-2` | `#D3CEC1` | 可交互边界 | 装饰 |
| `accent`（朱红） | `#B3341F` | 主操作、选中、排名上升 | **5.87:1** |
| `accent-bg` | `#F8E6E1` | 朱红浅底 | 其上朱红 **5.08:1** |
| `down`（松绿） | `#3F6B52` | 排名下降 | **5.85:1** |
| `gold` | `#8A6A1F` | 评分、前三名序号 | 4.83:1；在 `#FBF4E2` 上 4.60:1 |

**为什么不是 v2 的宣纸米黄**：米黄 + 赭石是一套「仿古」语言，适合纯阅读场景；但榜单/搜索/详情是**信息页**，需要更高的明度分离才能让发丝线和数字立住。纸白（`#FBFAF7`）比米黄冷一档，与阅读页的暖米黄（`#F3EBD9`）形成有意的「外壳 / 内页」对比——像书的封面与内文纸。

**为什么升用朱红、降用松绿**：中文语境里红=涨，绿=跌，与西方股市相反。用 `#3F6B52` 而不是鲜绿，避免与朱红形成圣诞配色。

### 3.2 颜色（阅读页，独立于外壳）

沿用 `ReaderPalette` 七槽，`dim` 已修正为过 AA：

| 方案 | background | text | title | dim | accent | rule |
|---|---|---|---|---|---|---|
| 米黄 paper | `#F3EBD9` | `#2C2620` | `#1A1611` | `#6B5F50`（5.24:1） | `#9C4A22` | `#E0D5BE` |
| 白 white | `#FFFFFF` | `#1F1D1A` | `#0C0B0A` | `#6E6252`（5.95:1） | `#9C4A22` | `#E6E3DE` |
| 浅绿 mint | `#E4EEDE` | `#1E2820` | `#131C16` | `#5F6B60`（4.68:1） | `#4A6B3F` | `#D0DDD0` |
| 夜色 dark | `#171A1E` | `#C8C7C2` | `#EBEAE5` | `#B5ABA0`（7.73:1） | `#D9A273` | `#2A2E34` |

阅读底色由用户显式挑选，**不跟随系统**（只有 `theme = "auto"` 才按系统深浅切夜色）。

### 3.3 字体

- 界面：**Noto Sans SC**（400 / 500 / 700）
- 阅读正文与数字标题：**Noto Serif SC**（400 / 700）
- 所有数字：`font-variant-numeric: tabular-nums`

| 角色 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| 页面大标题 | 34/40（衬线） | 700 | 书架「书架」、榜单「榜单」 |
| 区块标题 | 19/26（衬线） | 700 | 在架、男频阅读榜 |
| 书名（详情） | 23/31（衬线） | 700 | 详情页主标题 |
| 列表书名 | 14/20 | 500 | 榜单行、书架行 |
| 正文（界面） | 13/22 | 400 | 简介、书评 |
| 元信息 | 11–12/16–18 | 400 | 作者、分类、状态 |
| 微型标签 | 10/15 + 0.12em 字距 | 500 | 区块序号、`TOTAL` 这类栏目字 |
| 阅读正文 | 19/33（衬线） | 400 | 用户可调 14–30sp |
| 阅读页眉 | 11/16 + 0.08em | 400 | 书名 · 章节 |

中文版心（阅读页）：左右各 20dp，段间距 0.75 行，**段间空行而非首行缩进**（中文网文按段组织）。

### 3.4 间距 / 圆角 / 层级

- 间距：4dp 网格；页面边距 **20dp**（比 v2 的 16dp 宽一档，刊物需要更松的气口）；区块间距 28dp；行内 12dp。
- 圆角：`0`（卡片/输入/芯片/按钮）、`10`（封面）、`20`（底部抽屉）。**同屏最多两档**。
- 层级：全部 `0` 阴影；浮起只用「遮罩 + 顶部 1px 线」表达。
- 图标：18–22dp 线性，1.5–1.6px 描边，单一描边族。

## 4. 分屏规格

### 4.1 书架（`01-shelf.png`）

**结构**（自上而下，字号递减）：

1. **页头**：`10 月 29 日 · 周三`（10sp 栏目字）+ `书架`（34sp 衬线）+ `在架 2 本 · 昨日读了 143 分钟`（12sp）。
   - 「昨日读了 143 分钟」来自本地 `stats`，是真实数据，不是装饰。
2. **继续阅读卡**（全页唯一带边框的重点卡）：左 62×84 封面；右侧 `继续阅读` 栏目字 + 书名 18sp 衬线 + `第 2 章 说谎 · 第 14 段` + 66% 进度条；底部两格分隔按钮 `接着读` / `章节目录`。
   - 进度百分比**可算**：`ShelfItem` 有 `chapterId`，配合 `progress` 与章节总数；此处显示 66% 是「本章已读段落比例」，不是全书进度（见 §7 数据诚实性）。
3. **在架**（区块 01）：行式列表，每行 46×62 封面 + 书名 14sp + `作者 · 连载 · 1496 章` + 一条 54dp 迷你进度线 + 章位置 + 右侧徽标（`新 3` 朱红 / `已读` 墨灰）。
   - **实际实现去过掉「在架 N 本 · 查更新」这一整行**：分类已经在上面那排「全部 / 小说 / 漫画 / 短剧」芯片里，再写一遍「在架」是重复；本数挪进页头标题（`书架  12 本`），「查更新」挪进页头图标。一来一回省掉约 64dp，书架第一本书直接顶到工具栏下面。
4. **男频阅读榜**（区块 02）：直接用 `RankRow`——衬线序号（前三名朱红）+ 34×46 封面 + 书名 + `作者 · 分类` + **右侧两行数字**：`59.8 万` 在读、`↑1 / ↓1 / — 持平`。
5. **大家在搜**：设计初稿里放在书架的独立区块（两列 6 条 + `01`–`06` 序号）。
   - **实际实现搬到了搜索页，而且只在搜索框被点进去时露出**：热搜词本来就是「大家都在搜什么」，摆在书架上是块跟书架无关的内容；搬到搜索页一直挂着，又会让人以为这些词是「我搜过的」。所以做法是——平时只显示「最近搜索」，点了搜索框才把热搜词摊开（`SearchScreen` 的 `fieldFocused` + `HotWordsBlock`），点词直接当搜索词用。数据仍来自同一份 `state.hot`（`api.hotWords()`），发现页不再有这个区块。
6. **底部 tab**：书架 / 发现 / 短剧 / 我的，四项（≤5）。
   - **实际实现是「悬浮胶囊」而不是通栏**（`ui/FloatingNavBar.kt`）：`Surface(RoundedCornerShape(50))` + `shadowElevation = 12.dp` 叠在内容之上，不占布局高度，页面背景一直铺到屏幕下缘。选中项展开文字并用 `primary.copy(alpha = 0.12f)` 铺胶囊底，未选中只有 22dp 图标——四个入口在 360dp 宽的机型上也放得下，图标始终带 `contentDescription`，读屏不依赖展开态。
   - 底色取 `surfaceContainerHigh` 而非 `surface`：暗色主题下 `surface`（`0xFF1C1A16`）与页面底色（`0xFF14120F`）几乎同色，胶囊会糊在背景里。
   - 三处分页列表的底部留白跟着改成 `Space.navFloat = 80.dp`（`ShelfScreen.kt:123`、`DiscoverScreen.kt:129`、`ToolsScreen.kt:173`），保证最后一项能滚出胶囊之外。

**为什么书架不再是「网格」**：书架的核心问题是「我还要不要接着读」，不是「这本书好不好看」。行式列表能在同高度内多塞进进度、章位置、新章数三个状态，网格只能放一张封面。

**点书直接进正文**：书架是「接着读」的地方，点书目不再先进详情页，而是直接落到上次读到的章与段（`readerFromShelf = true`，阅读页返回键回书架而不是详情）。详情页（简介 / 书评 / 目录预览 / 下载 / 共享）改从长按书目的「分组」对话框里进，那里多了一个「查看书籍详情」；发现、榜单、搜索、作者页的书目点击**仍然**先到详情——那些场景用户还没决定要不要读。

### 4.2 榜单（`02-rank.png`）

这是 v3 信息密度最高的一屏，也是最能体现「用后端数据」的一屏：

- **榜种标签条**：`推荐榜 / 完本榜 / 巅峰榜 / 新书榜 / 漫剧榜 / 短剧榜` + 2dp 下划线。
  ⚠️ 设计初稿画的「男频 / 女频」在 Android 侧**做不到**（见 §1.1），已改回真实榜种。
- **阅读榜 / 新书榜**：次级分段（对应 `types`，只有这两项）。
- **分类芯片**（对应 `categories`，实测 16 个）：**默认折叠成一行**，行尾一颗「全部 16」，
  点开铺成三行、行尾变「收起」。折叠时**当前选中的分类一定留在这一行里**（前 5 个里
  没有它就顶掉最后一个）——否则用户看不出自己站在哪个分类下。分类本来就不多时
  （≤ 6 个）不折叠，省得为藏一个芯片还多出个按钮。选中态朱红实底。
  折叠前分类平铺三行，把书列表挤到 y≈712；折成一行后统计条上移到 y≈514，省约 200px。
- **统计条**：`TOTAL 200 · PAGE 1/20` + `统计于 09:12`（来自 `total` / `page` / `statistics_at`）。
- **榜行**（每行 70dp）：
  ```
  1    [封面]  人在诡异，靠第四天灾登顶至高          59.8 万在读
               我时糕手 · 连载 · 423 万字              — 持平
  ```
  四列对齐：序号右对齐 / 封面 / 书名+元信息 / **在读人数 + 升降**。
  - 序号 1–3 用朱红衬线，4–200 用 `ink-3`。
  - 升降：`↑ n` 朱红、`↓ n` 松绿、`0` 显示 `— 持平` 墨灰。**颜色 + 符号 + 文字三通道**，色弱可读。
  - 在读人数格式：`59.8 万` / `21.9 万` —— 万位截断到一位小数，等宽对齐。
- **统计条**：`TOTAL N 本` + 当前分类。
  ⚠️ 设计初稿画的「加载下一页 · 1 / 20」**做不到**：核心载荷 `has_more=false`、
  `next_offset=0`，一次给 30 本且不可翻页（见 §1.1）。
  实测补充：`offset` 参数确实会换一批书，但**同一 offset 连取四次，两两只重叠 0~2 本、
  顺序全不同**（完本榜重叠 11 本但顺序同样不稳）。也就是说榜单在上游是每次请求重新
  生成的推荐流，不是可以往后翻的固定列表；照 offset 递增去翻等于编造分页。

**为什么不用无限滚动**：榜单是「可比较的位置」，用户需要知道「我在第几页、还有多少」。固定底栏给出位置感，无限滚动会抹掉它。

### 4.3 详情（`03-detail.png`）

- **顶栏**：返回 / 分享 / 更多，透明压在内容上。
- **英雄区**：104×140 封面 + 书名 23sp 衬线 + `杀虫队队员 · 连载中` + 三个徽标（`悬疑脑洞` 描边 / `9.9 分` 金底 / `榜 1` 朱红）。
  - `榜 1` 只在「从榜单点进来」时出现（携带 `rank` 参数），是一种上下文记忆。
- **三列数字块**（`在读 / 章 / 字`）：上下各一条发丝线，中间竖分隔。数字用衬线 20sp。
- **主次操作**：实心朱红 `继续阅读 · 第 2 章`（52dp）+ 描边 `加入书架`（46dp）。下载、前 20 章、听书、作者页全部进「更多」菜单。
- **简介**：3 行截断 + 朱红 `展开`。
- **相关推荐**：74dp 宽横向卡。
- **目录预览**：4 行，右侧 `共 1496 章 ›`；当前章朱红标 `在读`。
- **书评**：一张卡（头像 + 昵称 + 金色评分 + 2 行正文），右侧 `19.5 万人点评 ›`。

### 4.4 阅读页（`04-reader.png`）

- **全出血**，无 Scaffold；状态下默认 chrome 全隐藏，只剩正文 + 底部常显进度线。
- **页眉**：居中 `十日终焉 · 第 2 章 说谎`，11sp + 0.08em 字距，`dim` 色，**只在正文顶部出现一次**，滚走即消失。
- **正文**：衬线 19/33，左右 20dp，`text-align: justify` + 两端对齐，段间 15dp（≈0.75 行）。
- **段评轨道**：整章固定 30dp 右轨道，有段评的段落显示圆角胶囊（`2.6k` / `412`），`hot=true` 的用朱红描边。无段评的段落留空——**正文右边界因此始终对齐**，这是刊物感的关键。
- **高亮**：`accent` 18% 叠加，不是整块铺色。
- **书签**：段落左侧 2dp 朱红细条，不用 emoji。
- **朗读中**：段落 `accent` 16% 叠加。
- **底部常显**：2dp 进度线 + `66%` + `2 / 1496`（当前章序号 / 总章数，来自 `chapters.indexOfFirst + 1`）。
- **底栏**（点击屏幕中央 60% 唤起）：目录 / 设置 / 听书 / 夜间，四图标 + 10sp 标签，全部跟随 `ReaderPalette` 换色。

## 7. 数据诚实性（本设计的红线）

界面上出现的每个数字都必须能从后端或本地文件里查到；查不到就不显示，**不编造**。

| 数字 | 来源 | 边界 |
|---|---|---|
| 在读人数 | `Book.readCount`（核心 `read_count`） | **能拿到**。注意上游还有 `read_count_all`（累计阅读），两者口径不同，界面只用 `read_count` |
| 排名升降 | ❌ **取不到** | 原生核心 `rank_data` 载荷无 `rankPosDiff`/`currentPos`。**不做**，不编造 |
| 榜单分页 | ❌ **取不到** | 载荷固定返回 30 本，`has_more=false`；同 offset 重取结果也不可复现。不画页码 |
| 名次序号 | 列表下标 + 1 | 这就是榜单语义本身，与上游 `rank` 一致 |
| 连载/完本 | `Book.status` | **`"0"` = 完本，`"1"` = 连载**（实测 40 条榜单样本：7 条 `"0"` 的末章全是「完结/番外/大结局」，33 条 `"1"` 均无完结信号）。适配层当前未解析该字段，需补 |
| 章位置 `2 / 1496` | `chapters.indexOfFirst { it.id == currentChapterId } + 1` | 找不到显示 `— / 1496` |
| 书架进度 % | `ShelfItem.chapterOffset` / 当前章段落数 | **只能显示「本章第 N 段」，不能显示全书百分比**——书架数据里没有章序号 |
| 昨日阅读 143 分钟 | `stats`（本地 `stats.json`） | 无记录时整行隐藏 |
| 段评条数 | `chapters/{id}/reviews` 的 `count` | `> 999` 显示 `1.2k`；`contentDescription` 保留真实数 |
| `TOTAL 200` | `RankingPage.total` | — |
| 已下载 483 章 | 本地 `offline/books/<id>/` 计数 | — |

## 8. 可访问性

- 触控目标 ≥48×48dp（图标视觉 18–22dp，热区撑开）。
- 所有前景文字对比度 ≥4.5:1（见 §3.1 实测表；`ink-3` 从初稿 `#8C877A` 的 3.43:1 改到 `#6E6A5C` 的 5.19:1）。
- 排名升降用 `符号 + 颜色 + 文字` 三通道；当前章用 `竖条 + 颜色 + 底色` 三通道。
- 图标按钮必须有 `contentDescription`；纯装饰图标 `contentDescription = null`。
- 系统字体放大 1.3× 不截断（所有正文用 `sp`，行高按倍数换算）。
- 横屏：书架行改双列，阅读正文加宽到 32dp 边距，行宽不超过 40 字符。

## 9. 与 v2 的差异汇总

| 项 | v2 | v3 | 理由 |
|---|---|---|---|
| 外壳底色 | `#FAF6F0` 宣纸米黄 | `#FBFAF7` 纸白 | 信息页需要明度分离，且与阅读页米黄形成「封面/内文」对比 |
| 强调色 | `#9C4A22` 赭石 | `#B3341F` 朱红 | 赭石偏棕，在纸白上不够「指示」；朱红仍属同一暖色系 |
| 圆角 | 8/14/18/24 四档 | 0/10/20 三档 | 刊物语言不需要卡片圆角；直角 + 发丝线更像表格 |
| 页面边距 | 16dp | 20dp | 更松的气口 |
| 榜单 | 网格卡片 | 行式 + 四列对齐 + 在读人数 | 用上 `read_count`（`rank_change` 取不到，未做） |
| 榜种筛选 | 无 | 六榜种标签条 × 分类芯片 | 用上核心 `rank_algo_list` / `sub_info_list` |
| 段评 | 正文下方一行 | 右缘固定轨道胶囊 | 不打断正文，右边界对齐 |
| 书架进度 | 无百分比 | 迷你线 + 章位置 | 用上 `chapterOffset` |
| 排序/翻页 | 芯片 | 分段控制 + 固定底栏页码 | 位置感 |
